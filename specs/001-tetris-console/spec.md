# Feature Specification: Windows Console Tetris (C++)

**Feature Branch**: `001-tetris-console`  
**Created**: 2026-05-08  
**Status**: Draft  
**Input**: User description: "C++ Windows Console Tetris game with spec-driven development"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Core Gameplay Loop (Priority: P1)

玩家启动程序后看到游戏棋盘，方块从顶部自动生成并下落。玩家可以使用键盘控制方块的移动和旋转。方块落地后固定在棋盘上，满行自动消除并增加分数。方块堆到顶部时游戏结束，显示最终分数。

**Why this priority**: 这是俄罗斯方块的核心玩法，没有它产品不具备任何价值。所有其他功能都建立在此基础上。

**Independent Test**: 启动程序后可用键盘控制第一个方块左右移动、旋转、下落、落地固定，能看见分数变化和行消除，堆满顶部后游戏结束。完全可独立验证。

**Acceptance Scenarios**:

1. **Given** 游戏刚启动, **When** 程序初始化完成, **Then** 显示空白棋盘、边界、分数为0，第一个方块出现在顶部
2. **Given** 方块正在下落, **When** 玩家按左方向键, **Then** 方块向左移动一格（未超出边界或碰撞时）
3. **Given** 方块正在下落, **When** 玩家按右方向键, **Then** 方块向右移动一格（未超出边界或碰撞时）
4. **Given** 方块正在下落, **When** 玩家按上方向键, **Then** 方块顺时针旋转90度（旋转后不碰撞时）
5. **Given** 方块正在下落, **When** 玩家按下方向键, **Then** 方块加速下落（软降）
6. **Given** 方块正在下落, **When** 玩家按空格键, **Then** 方块直接落到最底部并固定（硬降）
7. **Given** 方块落地, **When** 方块无法继续下落, **Then** 方块固定到棋盘上，生成下一个新方块
8. **Given** 棋盘某一行被填满, **When** 行消除触发, **Then** 该行被清除，上方所有行整体下移，分数增加
9. **Given** 新方块生成位置与已有方块重叠, **When** 碰撞检测触发, **Then** 游戏结束，显示最终得分

---

### User Story 2 - 彩色显示 (Priority: P1)

不同形状的方块以不同颜色显示。已固定的方块和当前下落的方块都能区分颜色。棋盘边框、空白区域和文字信息清晰可辨。

**Why this priority**: 彩色显示是用户体验的核心部分，直接影响可玩性。如果方块颜色无法区分，玩家难以判断方块形状和位置。

**Independent Test**: 启动游戏后，观察不同形状的方块是否有不同颜色；固定方块和下落方块是否都能保持颜色；边框和文字是否清晰。在 PowerShell 中验证无乱码。

**Acceptance Scenarios**:

1. **Given** 游戏中存在不同形状的方块, **When** 观察游戏画面, **Then** I/O/T/S/Z/J/L 方块各有不同颜色，可直观区分
2. **Given** 方块已固定在棋盘上, **When** 观察棋盘, **Then** 固定方块保持其原始颜色，与空白区域明显区分
3. **Given** 游戏运行中, **When** 观察画面, **Then** 棋盘边框使用清晰字符绘制，分数/行数/等级文字清晰，颜色正确

---

### User Story 3 - 编码与显示兼容性 (Priority: P1)

游戏在 Windows PowerShell / Windows Terminal 中运行不乱码。显示优先使用 ASCII 字符，避免 emoji 和复杂 Unicode。程序启动时设置控制台编码确保兼容 GBK 环境。

**Why this priority**: 如果显示乱码，产品完全不可用。必须在第一版就确保兼容性。

**Independent Test**: 在 Windows PowerShell (GBK 代码页 936) 和 Windows Terminal (UTF-8) 中分别启动游戏，确认界面无乱码，边框/方块/文字显示正常。

**Acceptance Scenarios**:

1. **Given** 系统代码页为 GBK (936), **When** 启动游戏, **Then** 程序自动处理编码，所有显示正常不乱码
2. **Given** 程序输出中文提示, **When** 在 GBK 环境下运行, **Then** 中文正常显示，不会变成乱码
3. **Given** 游戏使用边框字符, **When** 渲染棋盘, **Then** 使用 ASCII 字符（如 +, -, |, [, ], #）绘制，在所有终端中稳定显示

---

### User Story 4 - 方块完整特性 (Priority: P2)

支持经典 7 种方块（I/O/T/S/Z/J/L）的旋转系统。旋转时正确检测碰撞，不能穿墙或穿过已有方块。每种方块有独立的形状数据和旋转状态。

**Why this priority**: 方块是游戏核心机制。完整的旋转系统和碰撞检测确保游戏体验标准、可预测。

**Independent Test**: 在游戏中依次生成所有 7 种方块，各旋转 4 次验证形状正确；靠墙时旋转验证墙踢行为；方块不能穿过已有方块。

**Acceptance Scenarios**:

1. **Given** 方块靠近左边界, **When** 玩家旋转方块, **Then** 如旋转后超出边界则不旋转（或执行基本墙踢）
2. **Given** 方块下方有已固定方块, **When** 方块下落, **Then** 方块在固定方块上方停止，不会穿越
3. **Given** 方块旋转, **When** 旋转后位置与固定方块重叠, **Then** 旋转被阻止，方块保持原状
4. **Given** I/O/T/S/Z/J/L 方块依次生成, **When** 观察每种方块, **Then** 每种方块显示正确的形状和颜色

---

### User Story 5 - 游戏难度递增 (Priority: P2)

随着消除行数增加，游戏速度逐渐加快。玩家能够感受到游戏越来越快，挑战性逐步提升。

**Why this priority**: 难度递增是游戏长久可玩性的关键，但不是 MVP 的硬性要求——固定速度也能玩。

**Independent Test**: 持续消除行数，观察方块下落速度是否逐渐加快；验证速度增长曲线合理。

**Acceptance Scenarios**:

1. **Given** 玩家消除了一定行数, **When** 总消除行数达到升级阈值, **Then** 游戏等级提升，方块下落间隔缩短
2. **Given** 游戏等级提升, **When** 观察下落速度, **Then** 速度变化平滑可感知，不会瞬间过快

---

### User Story 6 - 代码模块化结构 (Priority: P2)

代码按模块拆分，不全部写在 main.cpp。核心模块包括 Game、Board、Piece、Renderer、Input，每个模块职责清晰，便于后续扩展。

**Why this priority**: 模块化是 spec-driven 开发流程的核心目标之一。良好的结构方便后续 spec 迭代添加新功能。

**Independent Test**: 检查代码文件结构，确认每个模块有独立的 .h/.cpp 文件；main.cpp 仅负责创建 Game 并启动；各模块可通过接口独立测试。

**Acceptance Scenarios**:

1. **Given** 项目源码, **When** 查看文件结构, **Then** 存在 Game.h/cpp、Board.h/cpp、Piece.h/cpp、Renderer.h/cpp、Input.h/cpp 模块
2. **Given** 查看 main.cpp, **When** 阅读代码, **Then** main 函数简短，仅做初始化并启动 Game 主循环
3. **Given** Board 模块, **When** 查看接口, **Then** 提供碰撞检测、方块固定、消行等方法，不依赖渲染或输入

---

## Edge Cases

- 方块在边界处旋转：当旋转后部分方块超出边界时，应阻止旋转或进行墙踢（简单实现先阻止旋转）
- 方块出生即碰撞：新方块生成位置被已有方块占据时，触发游戏结束
- I 方块横置在顶部：I 方块水平放置时宽度为4格，在棋盘顶部需要确保不越界
- 快速连续按键：用户快速连续按移动键时，每次按键都应正确处理，不丢失输入
- 空格硬降后立即生成方块：硬降落地后下一帧就生成新方块，不额外等待下落间隔
- 同时消除多行：一次消除 1-4 行时，分数计算正确（经典计分：1行100、2行300、3行500、4行800）
- 棋盘高度边界：方块不能移动到棋盘上方不可见区域
- PowerShell 窗口大小：程序不依赖特定窗口大小，使用固定棋盘尺寸（10x20）
- GBK 编码下控制台 API 行为：SetConsoleOutputCP 设置后颜色 API 正常工作的验证
- 程序异常退出：Ctrl+C 或关闭窗口不会导致控制台状态残留（颜色/光标等）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在 Windows 控制台中运行，启动后直接进入游戏循环
- **FR-002**: 系统必须周期性刷新画面，方块按固定时间间隔自动下落
- **FR-003**: 棋盘必须是 10 列 x 20 行的固定大小二维网格
- **FR-004**: 系统必须支持经典 7 种俄罗斯方块：I、O、T、S、Z、J、L
- **FR-005**: 每种方块必须有独立的形状定义（含所有旋转状态）和颜色
- **FR-006**: 玩家必须能通过键盘控制方块：左移（A/左箭头）、右移（D/右箭头）、软降（S/下箭头）、旋转（W/上箭头）、硬降（空格）、退出（Q/Esc）
- **FR-007**: 方块移动和旋转时必须进行碰撞检测，不能穿过边界或已有方块
- **FR-008**: 方块落地后必须固定到棋盘上，成为永久障碍物
- **FR-009**: 填满的行必须被清除，上方所有行整体下移
- **FR-010**: 系统必须根据消除行数正确计分，并显示当前分数、消除行数、等级
- **FR-011**: 新方块生成时发生碰撞必须触发游戏结束
- **FR-012**: 游戏结束后必须显示最终分数，并提示退出或重新开始
- **FR-013**: 不同方块必须使用不同颜色显示（使用 Windows 控制台颜色 API）
- **FR-014**: 显示字符优先使用 ASCII（如 []、##、..、空格、+、-、|），避免 emoji 和复杂 Unicode
- **FR-015**: 程序启动时必须设置控制台输出编码（SetConsoleOutputCP）以兼容 GBK/UTF-8 环境
- **FR-016**: 边框和文字渲染必须清晰，颜色不互相干扰
- **FR-017**: 代码必须按模块拆分：Game、Board、Piece、Renderer、Input、main
- **FR-018**: 游戏难度必须随消除行数递增（下落间隔递减）
- **FR-019**: 程序必须在 Windows PowerShell 和 Windows Terminal 中编译运行正常，无明显乱码
- **FR-020**: 第一版使用英文提示信息以降低编码兼容风险

### Key Entities

- **Board（棋盘）**: 10x20 的二维网格，存储每个单元格的颜色和占用状态。负责碰撞检测、锁定方块、行消除逻辑。
- **Piece（方块）**: 表示当前活跃的方块，包含形状矩阵（含旋转状态）、在棋盘上的位置 (x, y)、颜色。支持移动、旋转、硬降操作。
- **Game（游戏管理器）**: 管理游戏状态（运行中/结束/暂停）、主循环、分数/等级/行数、方块生成、下落定时器、输入调度。
- **Renderer（渲染器）**: 负责将游戏状态绘制到控制台，包括棋盘网格、当前方块、边框、得分信息、颜色设置、光标隐藏。
- **Input（输入处理）**: 非阻塞读取键盘输入，处理方向键、空格等功能键，返回标准化的游戏操作指令。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 Windows PowerShell (GBK code page 936) 中编译运行，游戏界面无任何乱码
- **SC-002**: 在 Windows Terminal 中编译运行，游戏界面无任何乱码
- **SC-003**: 所有 7 种方块能以不同颜色正确显示，固定方块与下落方块颜色可区分
- **SC-004**: 方块自动下落间隔默认约 800ms，可随等级提升缩短至最低约 100ms
- **SC-005**: 方块碰撞检测正确率 100%：无穿墙、无穿块、无边界越界
- **SC-006**: 行消除逻辑正确：单行/多行同时消除后棋盘状态无错误
- **SC-007**: 分数计算准确：1行=100, 2行=300, 3行=500, 4行=800，硬降加分正确
- **SC-008**: 游戏结束触发正确：方块生成碰撞即结束，不会出现卡死
- **SC-009**: 键盘输入响应及时，无明显延迟（< 50ms）
- **SC-010**: 代码模块化清晰，main.cpp 不超过 30 行，核心逻辑分布在独立模块中
- **SC-011**: 使用 C++17 或 C++20 标准，仅依赖标准库 + Windows 控制台 API，无需额外第三方库

## Assumptions

- 目标运行环境是 Windows 10/11，使用 PowerShell 或 Windows Terminal
- 编译工具使用 MSVC (Visual Studio) 或 MinGW-w64 (g++)
- 控制台窗口大小足够显示 10x20 棋盘 + 侧边信息面板（建议 80x25 以上）
- 玩家熟悉经典俄罗斯方块的基本玩法
- 第一版不需要菜单、音效、存档、排行榜、暂停功能
- 方块旋转系统使用 SRS (Super Rotation System) 的简化版本：先尝试旋转，碰撞则阻止（不做复杂墙踢）
- 下一个方块预览、幽灵方块（ghost piece）功能留到后续迭代
- 游戏默认使用英文提示，避免 GBK 编码下的中文字符乱码问题
- 控制台编码处理使用 SetConsoleOutputCP(CP_UTF8) 或保持系统默认，优先保证 ASCII 稳定显示
- 不需要跨平台支持（仅 Windows），不依赖 ncurses 或其他 Unix 终端库
